# Редактор структуры страницы

Тестовое задание. Ниже — разбор по пунктам задания: что требовалось и что сделано,
с путями до кода.

Бекенда нет, вместо него мок в памяти: задержка, версия документа, ответ 409.

Стек: Vite, React 19, TypeScript, Zustand, Feature-Sliced Design, shadcn на Base UI
и Tailwind для редактора, SCSS-модули для страницы, @dnd-kit, Vitest и Testing Library.

## 1. Интерфейс редактора

**Рабочая область из трёх частей.** `pages/editor/ui/EditorPage.tsx` — грид из трёх
колонок, сверху тулбар.

| Часть                                | Где                       |
| ------------------------------------ | ------------------------- |
| панель добавления блоков             | `widgets/block-palette`   |
| список блоков страницы               | `widgets/block-structure` |
| настройки выбранного блока           | `widgets/block-inspector` |
| отмена, повтор, статус, предпросмотр | `widgets/editor-toolbar`  |

**Типы блоков.** Тип блока определяет набор его полей — `entities/page-block/model/types.ts`.

| Тип         | Настройки       | Отображение   | Компонент                            |
| ----------- | --------------- | ------------- | ------------------------------------ |
| Текст       | текст           | абзац         | `entities/page-block/ui/TextBlock`   |
| Изображение | адрес, описание | картинка      | `entities/page-block/ui/ImageBlock`  |
| Кнопка      | подпись, ссылка | кнопка-ссылка | `entities/page-block/ui/ButtonBlock` |

Поля инспектора разведены по типам через `switch`, в `default` стоит `assertNever`.
Добавление четвёртого типа блока не соберётся, пока не дополнены все места, которые
это должны учитывать: рендер, инспектор, сравнение блоков, создание.

Пустой адрес картинки даёт плашку «Изображение не выбрано», нерабочий —
«Изображение не загрузилось». После исправления адреса картинка грузится снова.

**Действия над блоками.** Все в `features/block-editing/model/blockEditing.ts`.

| Действие       | Как работает                                                   |
| -------------- | -------------------------------------------------------------- |
| добавление     | кнопка типа в палитре, блок уходит в конец и сразу выбирается  |
| выбор          | клик по заголовку карточки или по её превью                    |
| редактирование | поля инспектора справа                                         |
| дублирование   | копия встаёт сразу за оригиналом, новый `id`, содержимое то же |
| удаление       | кнопка в карточке                                              |
| порядок        | перетаскивание за ручку слева, `@dnd-kit`                      |

Перестановка двигает элементы массива, объекты блоков не пересоздаются — это отдельно
проверяется тестом по ссылке, а не по содержимому. Тянуть можно только за ручку: если
повесить жест на всю карточку, кликом по ней нельзя будет выбрать блок.

**Режим предпросмотра.** `widgets/page-preview`. Открывается на весь экран вместо
редактора — `EditorPage` возвращает предпросмотр вместо раскладки, поэтому ни палитры,
ни настроек, ни карточек в нём физически нет. Остаются кнопка возврата, переключатель
ширины (десктоп 1280, планшет 768) и статус сохранения.

Внутри рисуется тот же `PageCanvas`, что и в карточках списка, — карточка показывает не
схему блока, а сам блок в уменьшенном виде.

## 2. История изменений

| Требование задания                                | Как сделано                                                            |
| ------------------------------------------------- | ---------------------------------------------------------------------- |
| Undo и Redo, глубина до 20                        | `shared/lib/history.ts`, `HISTORY_DEPTH = 20`, старые шаги вытесняются |
| `Ctrl+Z` и `Ctrl+Shift+Z`                         | `features/history-navigation`, плюс `Ctrl+Y`                           |
| новое изменение после Undo очищает ветку Redo     | любая запись в историю очищает список повторов                         |
| выбор блока и открытие настроек — не изменение    | выделение лежит в отдельном хранилище, документа не касается           |
| последовательный ввод склеивается в разумные шаги | склейка по ключу «блок плюс поле», окно 600 мс без нажатий             |
| служебные состояния в историю не попадают         | статус и версия лежат в другом хранилище, попасть в историю не могут   |

**Как устроено.** Блоки и история — в `entities/page-document/model/documentStore.ts`.
Статус сохранения, версия документа и конфликт — в `syncStore.ts`. Выделенный блок и
режим предпросмотра — в своих фичах. Это разные хранилища, поэтому служебное состояние
попадает в отмену не «если не забыли проверить», а никогда.

Все изменения блоков идут через одну функцию `applyBlocks`. Другого пути изменить
документ нет, значит нельзя случайно поменять блоки мимо истории и мимо автосохранения.
Отмена и повтор тоже считаются изменением документа и запускают сохранение; если
откатывать нечего, ничего не происходит и лишний запрос не уходит.

**Про склейку ввода.** Ключ склейки — идентификатор блока плюс имя поля, например
`blk_7f2a:text`. Пока ключ тот же и пауза между нажатиями меньше 600 мс, шаг истории
заменяется на месте. Окно отсчитывается от последней буквы, а не от начала набора,
поэтому непрерывный набор остаётся одним шагом сколько угодно долго и закрывается
паузой. Серия дополнительно рвётся, когда поле теряет фокус, когда выбран другой блок и
при отмене. Добавление, удаление, дублирование, перестановка и выравнивание ключа не
передают — это всегда отдельный шаг.

**Про горячие клавиши.** Слушатель висит на `window` и перехватывает событие раньше
всех. Две мелочи, на которых такие редакторы обычно ломаются:

- `preventDefault` вызывается всегда, в том числе когда курсор стоит в поле ввода.
  Иначе браузер откатит текст в поле своей собственной историей, и приложение
  разойдётся с тем, что видно на экране.
- Клавиша сравнивается по `event.code`, а не по `event.key`: на русской раскладке
  `Ctrl+Z` приходит как «я».

Ядро истории — обычный модуль без React, время приходит параметром, поэтому тесты
обходятся без подмены таймеров.

## 3. Автоматическое сохранение

| Требование задания                                 | Как сделано                                                                  |
| -------------------------------------------------- | ---------------------------------------------------------------------------- |
| сохранение через 700 мс после последнего изменения | таймер сбрасывается на каждое изменение                                      |
| одновременно только один запрос                    | флаг занятости, второй запрос не стартует                                    |
| можно продолжать редактирование во время запроса   | движок не трогает ни поля, ни документ                                       |
| новые изменения уходят следующим запросом          | после ответа сразу уходит второй запрос, без повторных 700 мс                |
| ответ не перезаписывает более свежие правки        | сохранённой считается отправленная версия, ответ в редактор не подставляется |
| статусы в интерфейсе                               | «Есть изменения», «Сохраняется», «Сохранено», «Ошибка сохранения»            |

**Как устроено.** Движок — `features/document-sync/model/createDocumentSync.ts`. Живёт
вне React, следит за счётчиком изменений документа напрямую. Таймер и флаг занятости —
переменные внутри него, поэтому весь блок гонок тестируется подменными таймерами и
подставным api, без единого рендера.

Порядок такой: изменение — статус «Есть изменения» и запись черновика — таймер на 700 мс —
запрос. Пока запрос в пути, новый не стартует. После ответа, если счётчик изменений
успел уйти вперёд, запрос уходит повторно сразу: 700 мс уже отработали, ждать второй раз
нечего.

**Самое важное место.** Сохранённой отмечается та версия документа, которую отправили, а
не та, что сейчас на экране. Если пока запрос шёл пользователь успел напечатать ещё,
документ остаётся несохранённым и уедет следующим запросом. И блоки из ответа сервера
никогда не подставляются в редактор: мы отправили ровно то, что у нас есть, а подстановка
ответа как раз и стёрла бы набранный за это время текст.

Ошибка не запускает повтор сама. Статус «Ошибка сохранения», рядом кнопка «Повторить».
Следующая правка пользователя тоже запустит цикл заново.

**Mock API** — `entities/page-document/api/mockServer.ts`, контракт из задания:

```ts
getPage(): Promise<PageDocument>
savePage(input: { blocks: PageBlock[]; version: number; force?: boolean }): Promise<PageDocument>
```

`pageApi.ts` рядом — тонкая обёртка, именно её импортируют фичи; при появлении бекенда
меняется только она. На входе и выходе мока стоит `structuredClone`, чтобы клиент и
«сервер» не делили одни и те же объекты, иначе тесты были бы зелёными при сломанном коде.

## 4. Конфликт версий

| Требование задания                               | Как сделано                                                         |
| ------------------------------------------------ | ------------------------------------------------------------------- |
| 409 с актуальной серверной версией               | мок отдаёт копию своего документа вместе с ошибкой                  |
| показать локальную и серверную версии            | диалог с двумя колонками и номерами версий, расхождения помечены    |
| принять серверную или перезаписать её локальной  | две кнопки, `features/conflict-resolution/model/resolveConflict.ts` |
| до выбора документ доступен без потери изменений | сохранение замирает, редактор — нет                                 |
| способ вручную симулировать внешнее изменение    | панель «Проверка сценариев», `widgets/dev-panel`                    |

**Что происходит при 409.** Замирает только сохранение: запросы не уходят, статус
«Конфликт версий». Текст при этом правится дальше, диалог можно закрыть и открыть заново
кнопкой «Разрешить» в тулбаре. Без этой заморозки получилась бы бесконечная очередь
ответов 409.

Диалог показывает не снимок на момент ошибки: в хранилище лежит только серверная версия,
своя читается прямо при отрисовке. Поэтому правки, сделанные при открытом конфликте,
видны в левой колонке сразу.

Расхождения помечаются по блокам: изменён, переставлен, есть только с одной стороны.
Сравнение — поле за полем (`entities/page-block/lib/isSameBlock.ts`), а не через
`JSON.stringify`, который зависит от порядка ключей и даёт ложные срабатывания.

**Оставить свою.** Базовая версия поднимается до серверной, и запрос уходит с флагом
`force`. Обновить версию тут обязательно — иначе сервер вернёт 409 второй раз, уже на
принудительном сохранении.

**Принять серверную.** Серверные блоки применяются через тот же `applyBlocks`, то есть
становятся обычным шагом истории. `Ctrl+Z` сразу после этого вернёт вашу версию — правки
не теряются навсегда. Решение осознанное.

## Как проверить руками

Кнопка «Проверка сценариев» в левом нижнем углу открывает панель:

- **Изменить документ на сервере** — поднимает версию на сервере, следующее сохранение
  упрётся в 409 и откроет диалог конфликта
- **Задержка ответа** — растянуть окно запроса и успеть поправить документ, пока он
  сохраняется
- **Вероятность ошибки** — состояние ошибки и кнопка повтора

Черновик: поправить что-нибудь и перезагрузить страницу в течение 700 мс.

## Сверх задания

- **Выравнивание и отступы** сверху и снизу у каждого блока.
- **Черновик в `localStorage`.** Пишется на каждое изменение, удаляется после успешного
  сохранения. История в черновик не пишется. При загрузке черновик применяется поверх
  серверного документа, а если версии разошлись — ушли с несохранённым, а документ за это
  время поменяли — открывается тот же диалог конфликта. Отдельного кода это не
  потребовало.
- **Разделение стилей редактора и страницы.** Редактор — Tailwind и shadcn. Страница —
  SCSS-модули со своими переменными `--page-*`, объявленными не в `:root`, а на
  классе-обёртке канваса. Канвас ничего значимого не наследует от редактора, тёмная тема
  редактора страницу не покрасит. Границу сторожит правило eslint: из
  `entities/page-block/ui` нельзя импортировать компоненты редактора.
- **Один компонент канваса на два места** — предпросмотр и карточки списка. В компактном
  виде меняются только высота и обрезка картинки.
- **Доступность:** статус сохранения объявляется вслух, у иконочных кнопок есть подписи,
  превью внутри карточки помечено `inert`, чтобы ссылки в нём не ловили фокус.
- **CI** — typecheck, lint, стили, тесты, сборка.
- **Мемоизация карточек** — при вводе текста перерисовывается только превью
  редактируемого блока, на это есть тест.

## Структура

```
src/
├── app/                 точка входа, загрузка документа, глобальные стили
├── pages/editor/        трёхколоночная раскладка
├── widgets/             палитра, структура, инспектор, тулбар, предпросмотр, панель проверки
├── features/            правка блоков, выделение, перестановка, история,
│                        синхронизация, разрешение конфликта, предпросмотр
├── entities/
│   ├── page-block/      типы блоков, рендер на канвасе, сравнение версий
│   └── page-document/   документ, хранилища, мок API
└── shared/              история, ошибки, константы, утилиты, компоненты shadcn
```

Импорты идут только сверху вниз по этому списку. Внутри одного слоя слайсы друг друга не
трогают: `page-block` о документе не знает, а `page-document` берёт типы блоков через
отдельный файл `@x/page-document.ts`.
